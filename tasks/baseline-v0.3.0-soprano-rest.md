# mokuren v0.3.0-in-progress major-mode chorale baseline (soprano-rest phrase splitting)

Generated by `examples/chorale_benchmark.rs` (fixture format v3) against a *re-extracted* corpus — the same music21 install and `tools/music21_chorale_extractor.py` as `tasks/baseline-v0.2.0-secondary-dominants.md`, but the extractor no longer skips a chorale for having a soprano rest (it now emits a `REST` event instead — see the file header comment in both). Titles, catalog numbers, and mokuren's own computed statistics only — no encoded musical content, same non-vendoring stance as prior baselines.

**What changed and why**: `Melody`/`Composer::harmonize` still only ever see a plain, rest-free `Vec<Note>` — unchanged. A new `MelodyLine` type (`src/melody.rs`) can hold `Note`/`Rest` events; its `phrases()` method splits at each rest into independent contiguous note runs, matching how a breath rest actually functions in chorale writing (a phrase boundary, not a gap inside one continuous harmonic idea — confirmed against real data: of the 75 chorales the old extractor skipped for a soprano rest, 47/75 have only 1–2 single-beat rests, consistent with a breath mark). `examples/chorale_benchmark.rs` builds a `MelodyLine` per chorale, harmonizes each phrase independently through the exact same `Composer::harmonize` path a rest-free chorale uses, and only counts a chorale as **covered** if *every* phrase harmonizes — a stricter bar than "any phrase worked," chosen so this number stays comparable to the pre-rest-support baselines rather than becoming a silently looser metric.

**Corpus grew from 144 to 182 chorales** (+38, +26%) — the entire major-mode corpus is now attemptable except for a genuine data gap (unrepresentable duration, missing part, or an ATB gap at a soprano onset). The "soprano rest" exclusion bucket (75 chorales in the v0.2.0 baseline) is gone entirely.

**Comparison against `tasks/baseline-v0.2.0-secondary-dominants.md`**: coverage on the *original* 144-chorale set is unchanged and fully verified — every one of the 136 previously-covered chorales is still covered (checked by diffing the two baselines' covered-chorale lists: zero regressions). On the *expanded* 182-chorale set: **94.5% coverage (172/182)**, statistically the same rate as before (94.4%) but over a meaningfully larger, harder-to-reach population — 36 of the 38 newly-admitted rest-containing chorales harmonized in full.

**The 10 failures**, same taxonomy as v0.2.0 plus one new instance of the known gap:

- **7 search-exhausted** (Riemenschneider 80, 135, 183, 230, 234, 272, 368 phrase 5/6): a wider beam finds a path in every case (recoverable at width 64–512, same known beam-width/vocabulary-size trade-off as v0.2.0 — see README limitation #4). Two of these (135, 230) are the *same* two chorales flagged as beam-width-recoverable in the v0.2.0 regression check; they behave identically here.
- **3 rule conflict (chordal seventh resolution)** — the same unfixed non-chord-tone gap from v0.2.0 (Riemenschneider 40, 202: a soprano note forced into a formal chordal-seventh role that must resolve by step, but the real melody leaps a third — almost certainly a decorative passing tone, which mokuren has no model for). **Riemenschneider 132** (phrase 1/2) is a *third* instance of this exact gap, newly visible only because 132 has a soprano rest and was excluded entirely before this feature — direct evidence the gap is a real, recurring pattern in the repertoire, not a one-off.

Reproduce: `python3 tools/music21_chorale_extractor.py -o <dir>` then `cargo run --release --example chorale_benchmark -- <dir> --report tasks/baseline-v0.3.0-soprano-rest.md`. To bisect one chorale directly (works the same for a multi-phrase chorale — each phrase is reported separately): `cargo run --release --example chorale_benchmark -- <dir> --bisect "<name substring>"`. Extracted `.chorale` files are never committed (deleted after each run, per "reference, don't vendor").
